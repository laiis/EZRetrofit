### 1. Phase 2: 基礎架構建設 (Foundational Infrastructure)
*   **T004**：建立 `EZRetrofitHelper` 類別，提供執行緒安全的實例化與單例管理。
*   **T005**：在 `EZRetrofit` 中加入 `setLogger(EZLogger)` 設定方法，並實作基於 Java 標準 `System.err` 的日誌紀錄後備（Fallback）方案，避免直接依賴 Android 平台的 Log API。

### 2. Phase 3: Cookie 管理與清除過期資料 (Cookie Management & Expiry Handling)
*   **T006**：於 `PersistentCookieStoreTest` 撰寫單元測試，驗證依 Cookie 名稱清除、無尾隨逗號序列化及損毀資料之解碼處理。
*   **T007**：修正 `PersistentCookieStore.remove()` 方法，將清除鍵值從網域（Domain）改為 Cookie 的名稱（Name），以確保能精準清除特定 Cookie。
*   **T008**：修正 `PersistentCookieStore.join()` 方法，修復序列化字串尾隨逗號的格式錯誤。
*   **T009**：當遇到損毀或無法解碼之 Cookie 時，透過 `EZLogger` 輸出警告日誌，而非直接回傳 null 或崩潰，提升容錯能力。

### 3. Phase 4: 多執行緒環境安全建立 Retrofit 服務 (Thread-Safe Service Creation)
*   **T010**：於 `EZRetrofitTest` 新增多執行緒併發壓力測試（10 執行緒，1000 次迭代），驗證 Base URL 與實例建立的執行緒安全性。
*   **T011**：於 `CallManagerTest` 新增 `CallManager.cancelAll()` 的多執行緒安全單元測試。
*   **T012**：優化 `EZRetrofit.create()` 方法，使用 `volatile` 快取變數並實作 Java 雙重鎖定模式（Double-Checked Locking），確保執行緒安全性。
*   **T013**：重構 `CallManager` 類別，將內部儲存連線的集合改為執行緒安全的 `ConcurrentLinkedQueue`，防止併發修改異常。

### 4. Phase 5: 安全性 - 憑證釘選使用強雜湊演算法 (Certificate Pinning Security)
*   **T014**：新增 `EZRetrofitTrustManagerTest`，測試 SHA-256 與 SHA-1 憑證釘選的驗證邏輯。
*   **T015**：更新 `EZRetrofitTrustManager` 以強制使用 SHA-256 標準，拋棄弱雜湊演算法（如 SHA-1），並妥善處理空釘選清單，避免空指標異常（NPE）。
*   **T016**：限制 `SupportAllTlsSocketFactory` 僅能使用現代 OkHttp 推薦之安全加密套件（`ConnectionSpec.MODERN_TLS.cipherSuites()`）。

### 5. Phase 6: 防止測試用 TrustManager 誤用於生產環境 (Environment Segregation)
*   **T017**：於 `DefaultTestingTrustManagerTest` 新增環境驗證測試，確保測試用 TrustManager 在生產環境會拋出異常。
*   **T018**：更新 `DefaultTestingTrustManager`，在 `BuildConfig.DEBUG == false` (生產環境) 時，主動拒絕運作並拋出 `IllegalStateException`，防止 TLS 機制被繞過。

### 6. Phase 7: 例外處理透明化與防禦性程式碼 (Exception Transparency)
*   **T019**：新增 `SSLFactoryManagerTest` 測試，驗證設定缺漏時的錯誤阻斷邏輯。
*   **T020**：更新 `SSLFactoryManager.build()` 方法，當設定不完全時主動拋出 `IllegalStateException`，拒絕隱性失敗。
*   **T021**：修正 `CallManager` 中的標籤驗證，改為正向邏輯判斷（`tag != null && !tag.isEmpty()`），避免無效標籤被登錄。
*   **T022**：若未呼叫 `initial()` 即呼叫 `EZRetrofit.create()`，主動拋出明確的異常說明，引導開發者正確初始化。

### 7. Phase 8: 精緻化與跨切關注點處理 (Polish & API Refactoring)
*   **T023**：修正 `RetrofitConf` 中拼字錯誤的 API（例如 `getCertficatePinner` 修正為 `getCertificatePinner`），並將舊方法加上 `@Deprecated` 標籤，確保向下相容性。
*   **T024**：為未使用的欄位 `mProtocol` 與 `mCertPins` 加入註釋，標明其為保留或未使用的欄位。
*   **T025**：驗證 `quickstart.md` 中所有程式碼範例的正確性，確保文件與最新實作完全一致。
